# Tennis Simulator

3D-симулятор большого тенниса на Unity (URP, новая Input System, Cinemachine). Сейчас реализован **подэтап 1** первого этапа: базовая игровая механика на прототипном корте.

## Запуск

1. Откройте папку проекта в Unity **6000.6.7f1** (нужна активированная лицензия).
2. При первом открытии `ProjectBuilder` сам создаст настройки URP, конфиги, материалы и сцену `Assets/TennisSim/Scenes/Prototype.unity` и откроет её.
3. Нажмите Play. Подключённый геймпад подхватывается автоматически.

Пересобрать сцену и ассеты: меню **Tennis → Rebuild Project Assets and Scene**.

Собрать игру для Windows: меню **Tennis → Build Windows Player**. Результат — `Build/Windows/TennisSimulator.exe`. В git билды не попадают; папку `Build/Windows` можно копировать только целиком.

## Как играть

**Удар:** нажать кнопку — подготовка, отпустить — замах. Ракетка приходит в точку контакта через 0,14 с после отпускания.

- Отпустили вовремя — **Perfect**: мяч быстрее и точнее.
- Держали кнопку через мяч — автозамах с опозданием, **Good**: играть можно всегда, но это не лучший результат.
- Ошиблись моментом или стоите далеко от мяча — **Poor** или промах.

Пока кнопка зажата, стик по-прежнему двигает игрока, а точка контакта подстраивается под его положение. Если стик отпущен или до мяча иначе не успеть, игрок сам бежит к точке контакта, а стик задаёт прицел. **F3** отключает автопозиционирование: движение полностью ручное.

**Подача (временная):** кнопка удара отпускает мяч из руки, затем его нужно ударить после отскока. Настоящая подача — подэтап 5.

| Действие | Клавиатура | Геймпад | Игрок 2 (клавиатура) |
|---|---|---|---|
| Движение и прицел | WASD | Левый стик | Стрелки |
| Только прицел | — | Правый стик | — |
| Ускорение | Shift | RT | Правый Shift |
| Авто (топспин, сторона по мячу) | Space | A / Cross | Num 0 |
| Удар справа | J | Крестовина → | Num 1 |
| Удар слева | K | Крестовина ← | Num 2 |
| С лёта | L | RB | Num 3 |
| Резаный | U | B / Circle | Num 4 |
| Плоский | H | X / Square | Num 5 |
| Свеча | I | Y / Triangle | Num 6 |
| Укороченный | O | LB | Num 7 |

Смэш не имеет своей кнопки: высокий мяч, взятый над головой, становится смэшем автоматически.

Первый геймпад управляет ближним игроком, второй — дальним. Дальним игроком по умолчанию управляет бот-партнёр, чтобы проверять механику в одиночку. **F2** передаёт его человеку, а второй геймпад делает это автоматически. **F1** скрывает подсказку.

## Графика

Модели, анимации и текстуры корта собираются скриптами из `Tools/Blender` (нужен Blender 5.2). Результат лежит в `Assets/TennisSim/Art`. Запускать из корня проекта; `<work>` — любая папка для промежуточных файлов:

```
blender -b --factory-startup --python Tools/Blender/prepare_meshes.py -- <player.glb> <racket.glb> <work> Assets/TennisSim/Art/Player
blender -b --factory-startup --python Tools/Blender/rig_and_animate.py -- <work> Assets/TennisSim/Art/Player
blender -b --factory-startup --python Tools/Blender/make_court_textures.py -- Assets/TennisSim/Art/Court
```

После этого выполните **Tennis → Rebuild Project Assets and Scene**.

Исходные GLB весят по 76 МБ и в репозиторий не входят. Первый шаг без них не запустить, но второй и третий работают, если промежуточные файлы первого шага сохранились.

## Тесты

В Unity: **Window → General → Test Runner**.

| Набор | Что проверяет |
|---|---|
| `Tests/EditMode` | Физика мяча, решатель ударов, качество контакта, судейство, розыгрыши ботов |
| `Tests/Input` | Все привязки геймпада и клавиатуры через виртуальные устройства |
| `Tests/PlayMode` | Настоящая сцена: боты играют, камера держит мяч и ближнего игрока, снимок в `Logs/Screenshots` |

Подробнее об устройстве проекта: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).
